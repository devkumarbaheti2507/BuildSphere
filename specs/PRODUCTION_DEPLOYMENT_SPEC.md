# Purpose

Define Phase 10 packaging for BuildSphere's own services and a controlled
staging deployment. This specification does not apply to project assets
generated by Project Service.

# Container model

- Backend images use the repository root as Docker build context.
- The selected service must be one of the ten checked-in backend workspaces.
- PNPM `9.15.0` performs a frozen workspace install, builds the selected service
  and its workspace dependencies, and deploys production dependencies only.
- Runtime images contain built JavaScript, production dependencies, templates,
  prompts, and SQL migrations. They exclude `.env`, `.git`, local caches,
  workspace `node_modules`, and pre-existing `dist` directories.
- Backend containers run as the Node image's unprivileged user and expose a
  service-specific `PORT` plus a `/health` Docker health check.
- The frontend build defaults `VITE_API_URL` to `/api`. A non-root Nginx
  runtime serves immutable assets, SPA fallback, security headers, and
  `/healthz` on port 8080.

# Runtime root

Flattened backend images set `BUILDSPHERE_ROOT=/app`. Entry points and the
migration runner use this explicit root in production and retain their current
monorepo-relative fallback for local development.

# Helm chart

- The chart deploys API Gateway, Auth, Project, Pipeline, Deployment,
  Monitoring, Logging, AI, Analytics, Notification, and Frontend workloads.
- Every workload receives a dedicated ServiceAccount with
  `automountServiceAccountToken: false`.
- Backend configuration comes from one non-secret ConfigMap and one existing
  Secret. The chart never creates a Secret.
- Required Secret keys are `DATABASE_URL`, `JWT_ACCESS_TOKEN_SECRET`,
  `JWT_REFRESH_TOKEN_SECRET`, and `INTERNAL_SERVICE_TOKEN`.
- GitHub and Kubernetes execution keys are optional unless their features are
  explicitly configured.
- PostgreSQL is external. The chart does not install PostgreSQL, Redis, MinIO,
  MailHog, a certificate controller, or an ingress controller.
- A pre-install/pre-upgrade hook runs migrations from the Auth Service image.
- All application containers run non-root with read-only root filesystems,
  dropped capabilities, seccomp, bounded resources, probes, and a writable
  memory-backed `/tmp` only.
- Ingress is optional and routes `/api` to API Gateway before `/` to Frontend.
  TLS references an operator-managed Secret.

# Safety defaults

- `KUBERNETES_EXECUTION_ENABLED=false` by default.
- Enabling execution requires non-empty exact API server hosts and allowed
  environments at chart-render time.
- Image tags must be explicit and must not be `latest`.
- Runtime credential values must not appear in chart values, templates,
  rendered manifests, logs, or CI arguments.
- CI builds images without login, push, signing, or registry mutation.

# Verification

- `helm lint --strict` must pass.
- Rendered YAML is parsed and checked for the expected workload set, secret
  absence, migration hook, pod security, probes, resources, and safe defaults.
- Each image definition is built from the repository root in CI.
- Local runtime smoke checks health endpoints.
- The chart includes a Helm test for frontend health, API routing, and the
  exact migration count.
- A local disposable cluster validates install, all workload readiness,
  migration, Helm test, upgrade, repeated migration/test, and cleanup.
  External or production cluster installation requires a separate explicit
  approval.
- The full Phase 0-9 regression gate remains green.

# Non-goals

- Provisioning cloud infrastructure or a managed Kubernetes cluster.
- Pushing images or managing a registry.
- Creating, rotating, or backing up production secrets.
- Installing PostgreSQL, Redis, MinIO, ingress, cert-manager, or monitoring.
- Enabling production Kubernetes mutation by default.
- High availability, autoscaling, network policy, service mesh, or disaster
  recovery automation in Phase 10.
